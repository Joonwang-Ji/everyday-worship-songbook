## 한 일 (설계문서 44장)
검토는 네 구역(서버 / app.js 1–2950 / app.js 2950–끝 + export.js / 모듈·CSS·sw)으로 나눠 읽기 전용으로 하고, 결과를 모아 한 번에 고쳤다. 새 기능은 넣지 않았다.

### 서버 `functions/api/[[path]].js`
- 시도 제한을 한 문장으로 세기(동시 요청으로 제한을 피하던 틈), 접속암호 로그인에 시도 제한(IP별 20번/10분).
- 본문이 객체가 아니면 400, 내부 오류문은 화면에 안 보냄(`console.error`), 0번 곡·콘티 404, 여러 개 삭제 90개 한도.
- 색인 2개, 시작 때 PRAGMA 줄이기, 필기 한도 초과 시 새 획 유지, 깨진 필기 줄 방어, 빈 콘티 안 남기기, R2 삭제 실패 기록, `lyricsOnly` 삭제.

### 화면 `public/app.js`
- `onLeave(fn)`(떠날 때 정리) · `leaveGuard`(저장 안 한 변경 확인) 두 장치를 라우터에 추가.
- 곡 편집: ⌘S·이미지 붙여넣기 리스너가 다음 편집 화면에 남던 것, 떠날 때 임시저장, 기본 송폼 Enter, 중복 제목 뒤 두 번 저장.
- 콘티 편집: 저장 안 하고 나갈 때 확인, 이미지 붙여넣기 리스너.
- 로그아웃 확인, 곡 열기만 해도 키가 저장되던 것, 연주 모드 이미지 실패 안내·화면 꺼짐 방지 해제, 저장본 `/me`로 열쇠 지우지 않기, 오류 카드 "다시 시도", 긴 알림 오래 보이기, 영어 오류문 가리기, 팀 입장 두 번 누름, 기호 버튼 `aria-label`.
- 죽은 코드 `SAMPLE`·`OTHER_KEY`·`nextSunday` 삭제.

## 제안 — 고치지 않고 남긴 것 (우선순위 순)
설계가 바뀌거나, 범위가 크거나, 확신이 낮아서 손대지 않았다. 다음 차수 후보.

1. **[보안·높음] 토큰 서명 비밀값.** 지금은 `CHURCH_CODE|ADMIN_PIN|ews-v1`이라, 접속암호를 아는 교인이 자기 토큰으로 6자리 관리자 PIN을 기기 안에서 전부 대입해 알아낼 수 있다(서버 시도 제한을 안 거침). 고치려면 Cloudflare에 `TOKEN_SECRET`(긴 무작위 글자)을 추가하면 된다 — **코드는 이미 이 값을 읽는다.** 단, 넣는 순간 모든 기기가 한 번 다시 로그인·팀 재입장해야 한다. 설치안내 7단계에 추가 필요.
2. [보안·중간] 관리자 PIN·초대코드·보관함 잠금이 전체 공용이라, 로그인한 한 사람이 5번 틀리면 모두 10분 잠긴다. IP별로 나눌지 결정 필요.
3. [중간] 필기 저장 경합: 두 기기가 같은 순간 저장하면 한쪽이 덮일 수 있음(서버 `rev` 조건부 UPDATE로 해결 가능).
4. [중간] 임시악보의 제목·키 칸이 악보 편집 권한 없는 팀장에게도 열려 있어, 고치면 콘티 저장이 계속 거절될 수 있음(추정, 미재현).
5. [중간] 관리자 화면: 추천 태그를 고치다가 다른 버튼(코드 재발급 등)을 누르면 편집 내용이 사라짐.
6. [낮음] 예배 종류·인도자 추가, 관리자 팀 만들기 버튼의 두 번 누름 방지. 팀 이름 중복은 서버가 막지 않음.
7. [낮음] 말투·낱말 통일: "저장했습니다/만들었어요", "삭제/지우기/빼기", "곡 편집/악보 편집", "관리자/앱 관리". 문구만 바꾸면 되지만 양이 많아 따로.
8. [낮음] 삭제 확인이 브라우저 창(`confirm`)과 앱 아래 창으로 섞여 있음.
9. [낮음] "악보 바로 올리기"로 만든 임시 악보 곡은 콘티를 취소해도 곡 목록에 남음(안내 문구 또는 자동 정리 — 설계 확인 필요).
10. [낮음] 서버: 업로드 `Content-Length` 없는 요청, 버전 삭제 뒤 `variant_map` 잔재, 구간 이관이 버전 본문을 안 다룸, 보관함 만들기 개수 제한.
11. [낮음] 클립보드 복사 코드가 세 곳에 따로 있음(`copyText`로 합치기).
12. **[필기·높음] 필기 화면을 열어 둔 사이 다른 기기에서 올라온 필기가 다음 저장 때 지워질 수 있음**(`ink.js` `loadPage`/`save`, 코드 경로로 확인·미재현). 3번(서버 `rev` 조건)과 함께 한 차수로 다루는 것이 좋다. 같은 계정으로 두 기기에서 동시에 필기할 때만 해당.
13. [중간] 후렴(`{soc}`~`{eoc}`) 안에 빈 줄이 있으면 구간이 둘로 나뉘어 `{ref: C}` 펼침·송폼 순서 보기에 절반만 나옴(`chord.js` `buildSections`). 파싱 규칙이라 따로 시험하며 고칠 것.
14. [중간] 서비스 워커 `VER`가 `v1` 고정이고 파일마다 따로 받아서, 배포 직후 느린 인터넷에서 새 파일과 옛 파일이 섞일 수 있음. 배포마다 `VER` 올리기 + 한 묶음으로 받기.
15. [중간] 필기 저장 실패(용량 초과, 사파리 개인정보 보호 창)가 조용함 — 안내 추가.
16. [낮음] 코드 인식: `G6/9`, `C(add9)`, `Cm(maj7)` 같은 표기가 이조되지 않거나 변환 때 `[?]`가 됨. 전조 메모 "(E7 E)" 반쪽 이조.
17. [낮음] CSS 정리: 안 쓰는 클래스 7개(`keyfixed`, `exp-row`, `ctools`, `ctools-row`, `te-mode`, `cv-pages`, `cv-steps`), 같은 선택자를 뒤에서 덮어쓴 곳 36개, 40px 미만 버튼(필기 도구·관리자 태그 칩), 12px 미만 글자 8곳, 가로 모드 노치 여백.
18. [낮음] 송폼에 악보에 없는 구간을 `×2`로 넣으면 "원본 구간이 없어요" 줄이 따라 나옴. "코드만 모두 지우기" 뒤 빈 줄 두 개.
19. [낮음] CSP를 보고 전용에서 실제 적용으로 바꾸기(실기기 콘솔에 위반 기록이 없는지 확인 뒤).
20. 시험 스크립트가 저장소에 없다(스크래치에서만 돌림). `tests/`에 Node·Playwright 시험을 넣어 두면 다음 차수가 싸진다.

## 테스트 환경 메모
- 저장소 루트에서: `wrangler pages dev public --d1 DB --r2 BUCKET --binding CHURCH_CODE=… --binding ADMIN_PIN=… --binding INVITE_CODE=… --binding TOKEN_SECRET=…` (functions 폴더가 있는 곳에서 실행해야 API가 잡힌다). 표는 서버가 처음 요청 때 스스로 만든다.
- 시드: `/api/login` → `/api/admin` → `/api/teams`(초대코드) → `/api/songs` → `/api/setlists`. Playwright는 `localStorage`에 `ews_token`·`ews_admin`·`ews_teams`(`[{id,name,team,leader}]`)·`ews_team_active`를 넣고 시작, 서비스 워커는 막는다.
- 송폼 글자의 표준 이름은 `Intro`(약어 `I` 아님) — `sections.js` 참고.
- 새 세션은 설계문서 10장, 36·36-b장, 44장과 이 문서를 먼저 읽을 것.
