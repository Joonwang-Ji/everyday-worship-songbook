# 인계문서 — 43차 (v0.43, 2026-11-19)
(42차 번호는 키 입력 보완(a~f)에 쓰여서 이번은 43차)

## 요청 (사용자)
코드 악보 필기 개선: (1) 도구창이 악보 하단을 가려 밑부분 필기·조회 불가 → 이미지 악보처럼 전체가 한 화면에 보이면서 필기, (2) 연주 모드 필기에서 확대 불가, (3) 곡 필기에서 확대·축소 때 마구 흔들림. 추가로 "송폼 순서가 바뀌면 필기가 갈 곳을 모르는 것 아닌가?" → C안(필기 창 개편 + 송폼 보강 1~3번) 진행, 도구 줄 위쪽·"너비에 맞춤" 버튼은 추천대로.

## 한 일 (설계문서 58장)
- 필기 = 전체 화면 필기 창. 위에 도구 줄, 아래에 악보 복사본을 한 화면에 맞춰 보임. 확대·이동은 변환 하나로만(흔들림 원인 제거). 곡 보기·연주 모드 공통(연주 모드 확대 가능). 넓으면 2단. `🔍 n%`·`↔ 너비` 버튼.
- 송폼: 회차 필기에 앞 구간 단서(`p`) 저장 → 순서가 바뀌어도 "B 다음 후렴"을 따라감. 못 찾는 필기는 정리 대상으로 안내(곡 보기는 송폼 지도로 판단). 송폼 저장 때 영향 알림.
- 서버: `cleanInk`가 `p`를 받음(구간 이름만). 서비스워커 캐시 v11.

## 시험
- Playwright 격리 페이지(서버 없이 chord·songform·ink 직접 로드) 35항목 통과(58-5).
- Node: `occMap`, `arrangeByForm`의 `occp` 확인.

## 사용자 확인 대기 (실기기)
1. 아이패드: 곡 보기·연주 모드에서 ✎ → 악보 전체가 한 화면에 보이는지, 맨 아래 줄까지 필기되는지.
2. 두 손가락 확대·축소가 매끄러운지(흔들림 없는지), 확대 상태에서 애플펜슬 필기가 정확한지.
3. 연주 모드(실제 곡·2단·쪽 넘기기)에서 필기 창이 정상으로 열리고 닫은 뒤 원래 쪽으로 돌아오는지.
4. 송폼 순서를 바꾼 뒤 연주 모드의 "이 회차만" 필기가 맞는 후렴을 따라가는지, 저장 때 알림이 뜨는지, 곡 보기의 "안 보이는 필기 정리" 안내.
5. 아주 긴 곡에서 처음 보이는 글자가 너무 작지 않은지(작으면 확대나 `↔ 너비`).

## 알아 둘 것
- 실제 앱(서버·D1)에서는 통합 확인을 못 했다(이 환경에 wrangler 없음). 격리 시험은 필기 창·앵커·송폼 로직까지.
- 곡 보기를 콘티에서 열었을 때는 칸 송폼을 몰라 "회차 사라짐" 판단을 하지 않는다(필기는 보존).
