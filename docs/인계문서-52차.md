# 인계문서 52차 — 콘티에서 연 곡 보기 좌우 넘기기

## 요청
콘티 보기에서 곡을 열었을 때(연주 모드가 아닐 때도) 좌우 스와이프로 이전·다음 곡으로 넘어가기. 손가락을 따라 화면이 움직이고 다음 곡이 자연스럽게 보이게.

## 한 일
- `app.js`: `bindSongSwipe` 추가(곡 보기 끝에서 `sl`이 있을 때 연결), `setlistSongHref`로 콘티 목록의 곡 주소 만들기를 함수로 빼서 공용화, `route()`가 화면을 떠날 때 `swipeable` 클래스 정리.
- `style.css`: `.swipe-ghost`(이웃 곡 안내 면)·`#app.swipeable`.
- 설계문서 65장.

## 시험
- `node --check app.js` 통과.
- 화면·터치 동작은 확인 못 함(실기기 필요).

## 사용자 확인 대기 (아이폰·아이패드)
- 콘티 → 곡 열기 → 좌우로 밀기: 화면이 손가락을 따라오는지, 이웃 곡 안내 면이 옆에서 따라오는지, 놓으면 다음 곡이 열리는지.
- 살짝만 밀면 제자리로 돌아오는지, 첫 곡·마지막 곡에서 안내 글이 뜨는지.
- 세로 스크롤·키 설정 창·펜슬 필기·이미지 악보 탭(확대 보기)이 전과 같은지.
- ← 를 한 번 눌렀을 때 콘티로 돌아가는지(넘긴 기록이 쌓이지 않는지).
- 이웃 곡은 안내 면(번호·제목·키)만 미리 보이고 실제 악보는 열린 뒤에 나타남. 악보까지 미리 보이길 원하면 다음 차수에서 구조를 바꿔야 함.

## 52차(b) — 안내 면 빼고 바로 이웃 곡 화면으로
- 요청: 이웃 곡 안내 정보가 뜬 다음에 화면이 열리는 게 번거로움 → 바로 다음 곡 화면으로.
- 안내 면(번호·제목·키)을 없앴다. 밀어서 넘기면 지금 곡이 밀려 나가고, 이웃 곡 실제 화면이 반대쪽에서 밀려 들어온다. 미는 동안 옆자리는 빈 배경.
- 시험: `node --check` 통과. 화면 확인 못 함. 확인할 것: 넘길 때 빈 화면이 눈에 거슬릴 만큼 길게 보이는지.

## 52차(c) — 이웃 곡 미리 받기
- 요청: 넘길 때 빈 화면 간격을 미리 받아서 줄이기.
- 곡 보기를 열면 앞·뒤 곡 데이터(+이미지 악보 첫 장)를 미리 받고, 넘겨서 열 때만 그 값을 쓴다. 코드 악보 곡은 데이터, 이미지 악보 곡은 첫 장까지.
- 시험: `node --check` 통과. 화면·속도 확인 못 함.
- 확인할 것: 넘길 때 빈 화면이 짧아졌는지, 이미지 악보 곡에서 첫 장이 바로 보이는지, 방금 고친 곡이 넘겨서 열 때 예전 내용으로 보이지 않는지(60초 안에 편집한 경우).
