## 한 일 (설계문서 46장)
- **4번**: 콘티 보기 맨 위에 흐름 카드(키 흐름·템포 흐름, 키가 많이 다르면 ⚠). 서버는 콘티 읽기에 `tempo`, `tags` 두 칸만 추가.
- **5번**: **이미 있는 기능**이었다(콘티 → 공유·저장 → "카톡용 텍스트 복사": 날짜·인도자·곡 순서·키·송폼·메모). 앞서 "없다"고 한 것은 확인 부족이었음. 새로 만들지 않음.

## 시험 (로컬 정적 서버 + Playwright, API 가짜 응답)
- Node: 키 거리(G→E♭ ⚠, G→A·G→Em·G→B♭·G→E 아님), 템포 분류(태그 우선·BPM 대체·없으면 ?).
- 브라우저 390×844, 1024×1366: 5곡 콘티에 카드 표시, 1곡·정보 없는 콘티는 카드 없음, 페이지 오류 0.
- 미시험: 실제 서버(D1)에서 `tempo`·`tags`가 오는지(쿼리에 두 칸 추가), 실기기, 서비스 워커 저장본(옛 저장본에는 두 칸이 없어 템포가 `?`로 보일 수 있음 — 한 번 열면 갱신됨).

1. 브랜치를 main에 병합(35차와 함께 올라가 있음) → 운영 반영 뒤 콘티 보기에서 흐름 카드 확인.
2. ⚠ 기준(5도권 4칸 이상)과 BPM 기준(120/90)이 현장 감각에 맞는지 → 다르면 숫자만 조정.
3. 카톡 텍스트에 BPM·키 흐름을 넣을지(원하면 다음 차수).
