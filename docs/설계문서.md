# Everyday Worship Songbook — 설계 문서 (v0.25, 2026-11-11)

찬양 악보집 웹앱. 가사 위에 코드를 얹은 악보를 저장하고, 키를 바꿔 보고, 팀별로 콘티를 공유한다.
이 문서는 새 대화에서 바로 구현을 시작하기 위한 인계 문서다.

## 1. 확정된 결정
| 항목 | 결정 |
|---|---|
| 악보 보관함 | 우리 교회 전체가 하나를 공유 |
| 사용 범위 | 우리 교회 여러 팀 |
| 코드 표기 | 영문 코드 (G, Am7, D/F#). 저장 형식은 ChordPro |
| 이미지 → 코드 | 반자동으로 시작(프롬프트 복사 → Claude 채팅 → 결과 붙여넣기 → 검수). 앱 안 Cloudflare 무료 AI 변환은 시험 후 채택 여부 결정 |
| 편집 권한 | 콘티는 해당 팀 팀장이 편집. 악보 편집은 팀장마다 관리자가 권한을 줄지 말지 개별 결정 |
| 콘티 공유 | 앱 안에서 팀원 열람 + 카톡용 텍스트 복사 + PDF/이미지 내보내기 |
| 배포 방식 | 터미널 없이 ZIP 전달 → GitHub 웹 업로드 → Cloudflare Pages 자동 배포 |
| 저장소 | GitHub·Cloudflare 모두 새로 만든다 (이미지피드와 분리) |

## 2. 인프라
- Cloudflare Pages + Pages Functions (API)
- D1: 곡, 콘티, 팀, 이력
- R2: 원본 악보 이미지/PDF
- 환경변수: `CHURCH_CODE`(교회 접속암호), `INVITE_CODE`(팀 생성용 초대코드), `ADMIN_PIN`(선택)
- 추천 저장소 이름: `everyday-worship-score`

## 3. 권한 구조
1. **교회 접속암호**: 앱 전체 입장 열쇠. 열람·이조 가능.
2. **팀 생성**: `INVITE_CODE` 필요. 만든 사람이 팀장이 되고 팀장 비번(PIN)을 설정, 팀 가입코드가 발급된다.
3. **팀원**: 팀 가입코드로 입장. 열람과 키 변경(본인 기기에만 저장)이 가능하다.
4. **악보 편집**: 관리자가 **팀장을 정할 때 악보 편집 권한을 줄지 말지 팀장별로 결정**한다. 권한이 있는 팀장만 악보를 저장·수정·삭제·분류할 수 있고, 권한이 없는 팀장은 악보를 열람·이조만 하며 콘티는 편집한다. 권한은 관리자 화면에서 언제든 켜고 끌 수 있다. 수정 이력과 되돌리기를 둔다.
5. **콘티 편집**: 그 팀의 팀장만.
6. **관리자(`ADMIN_PIN`)**: 팀 목록 확인, 팀장 지정과 팀장별 "악보 편집 권한" 켜기/끄기, 초대코드·팀 가입코드 확인/재발급, 팀 삭제.
7. 비번은 해시로 저장(Web Crypto PBKDF2), 로그인 후 서명된 토큰을 기기에 보관.

후순위 아이디어: 권한이 없는 팀장이 악보 오류를 발견했을 때 "수정 제안"을 보내고 관리자가 승인하는 기능.

## 4. 데이터 모델 (D1)
- `songs`: id, title, artist, original_key, tempo, youtube_url, tags, chordpro(본문), memo, created_at, updated_at
- `song_versions`: id, song_id, chordpro, edited_by_team, created_at (되돌리기용)
- `song_files`: id, song_id, r2_key, kind(image/pdf)
- `teams`: id, name, join_code, leader_pin_hash, can_edit_songs(악보 편집 권한, 기본 0)
- `setlists`: id, team_id, date, title, memo, created_at, updated_at
- `setlist_items`: id, setlist_id, position, song_id, key, form(송폼), memo
- 곡 사용 이력은 `setlist_items`에서 조회

## 5. 이조(키 변경) 스펙
- 입력: ChordPro 본문 (`[G]주님은 [C]나의 [D]목자`)
- 코드 파싱: 루트(A–G + #/b) + 퀄리티(m, maj7, 7, sus4, add9, dim, aug …) + 슬래시 베이스
- 반음 이동: ±1~±11. +/- 버튼, 목표 키 직접 선택
- 샵/플랫 표기: 목표 키에 따라 자동 선택(F키는 Bb, G키는 F#), 수동 전환 가능
- 카포 모드: "카포 N에서 치는 코드" 표시
- 렌더링: 코드를 가사 글자 위에 얹는 방식(코드 길이가 달라져도 정렬이 깨지지 않게, inline-block 위치 지정)
- 곡의 "우리 팀 기본 키"는 팀별로 저장, 콘티 안에서는 곡별로 그날의 키를 지정

## 6. 이미지 → 코드 변환
### 1단계 (반자동)
1. 앱의 "이미지로 추가" 화면에서 **변환용 프롬프트 복사** 버튼
2. Claude 채팅에 악보 사진(여러 장 가능) + 프롬프트 붙여넣기
3. 결과를 앱의 붙여넣기 칸에 입력 → 자동 정리 → **검수 화면**(원본 이미지와 나란히 확인) → 저장

프롬프트 초안:
```
첨부한 악보 이미지를 ChordPro 형식으로 변환해줘.
- 가사 위에 있는 코드는 해당 글자 바로 앞에 [코드] 형태로 넣어줘 (예: [G]주님은 [C]나의)
- 맨 위에 {title: 제목}, {key: 원래 키}를 넣어줘
- 절/후렴은 {comment: 1절}, {comment: 후렴} 형태로 구분해줘
- 보이지 않거나 불확실한 코드는 [?]로 표시해줘
- 설명 없이 변환 결과만 출력해줘
```

### 2단계 (시험)
- Cloudflare Workers AI 비전 모델(Llama 3.2 11B Vision)로 앱 안 자동 변환 시험
- 한 곡으로 한글 가사 인식과 코드 위치 정확도를 확인하고, 쓸 만하면 채택
- 부족하면 Claude API로 교체 (변환 부분은 교체 가능하게 따로 분리)
- 어느 방식이든 검수 화면 필수

## 7. 화면
1. **입장**: 교회 접속암호 → 팀 선택/가입 → (팀장) PIN
2. **곡 목록**: 검색(제목·가사·태그), 태그 필터, 최근 사용, 없으면 외부 검색 링크(Google/YouTube/Ultimate Guitar 검색 열기)
3. **곡 보기**: 가사+코드, 키 +/-/직접 선택, 카포, 글자 크기, 코드 숨기기(가사만), 원본 이미지 보기, 유튜브 링크
4. **연주 모드**: 큰 글씨, 화면 꺼짐 방지, 다크모드, 자동 스크롤, 좌우 스와이프로 콘티 안의 다음 곡
5. **곡 편집(팀장)**: ChordPro 입력 + 실시간 미리보기, 태그, 이미지로 추가, 수정 이력
6. **콘티 목록/편집**: 날짜별 목록, 곡 추가/순서 변경, 곡별 키·송폼·메모
7. **콘티 보기/공유(팀원)**: 앱 안 열람, "카톡용 텍스트 복사", PDF/이미지 내보내기
8. **팀 관리(팀장)**: 가입코드 확인/재발급, 팀원 안내

카톡용 텍스트 예시:
```
[11/16 주일예배 콘티]
1. 곡 제목 (G)
2. 곡 제목 (A)
3. 곡 제목 (E)
※ 메모
```

- 중복 곡 감지, 수정 이력/되돌리기, 사용 이력("최근 언제 불렀나")

## 12. 2차(팀·콘티)에서 확정·변경된 사항 (v0.2)
- **저장소/프로젝트 이름**: GitHub `everyday-worship-songbook`, Cloudflare Pages `everyday-worship-songbook`. (위 2장의 `everyday-worship-score`는 초안 이름)
- **악보 편집 권한**: `ADMIN_PIN`이 없을 때 누구나 편집되던 1차 동작은 제거. 편집 = 관리자 또는 (팀장 && `teams.can_edit_songs=1`). `ADMIN_PIN` 미설정 시 아무도 편집 불가(안내 문구 표시).
- **초대코드**: 환경변수 `INVITE_CODE`는 최초값. 관리자 화면에서 재발급하면 `settings.invite_code`(DB)가 우선한다.
- **토큰**: `member`(접속암호) · `admin` · `team`(팀원, 가입코드 해시 포함 — 가입코드 재발급 시 무효) · `leader`(팀장, PIN 해시 포함 — PIN 변경/재지정 시 무효). 헤더: `Authorization`, `X-Admin-Token`, `X-Team-Token`, `X-Leader-Token`.
- **PIN**: PBKDF2-SHA256(10만 회)로 `teams.leader_pin_hash`에 저장. 관리자·팀장 PIN·초대코드는 5회 실패 시 10분 잠금(`auth_fails`).
- **데이터 모델 추가**: `team_song_keys(team_id, song_id, key)` — 팀별 곡 기본 키 / `settings(k, v)` / `auth_fails(k, n, until)` / `setlist_items."view"`(`auto|chord|image`, 코드·이미지 악보 중 보여 줄 쪽). 기존 DB에는 `ensureSchema()`가 `PRAGMA table_info`로 확인해 `ALTER TABLE ADD COLUMN`.
- **곡 삭제**: 해당 곡의 콘티 항목과 팀 기본 키도 함께 삭제.
- **콘티**: 팀원 열람 / 그 팀 팀장만 편집. 항목마다 키·송폼·메모·보여 줄 악보. 이미지 악보는 화면에서 키가 바뀌지 않지만, 콘티 항목에 "부르는 키"를 직접 기록해 둘 수 있다(곡을 열면 이미지 위에 안내). 콘티에서 곡을 열면 그날의 키로 열리고 기기 개인 키는 덮어쓰지 않는다.
- **입장 흐름**: 접속암호 → 팀 가입/만들기(또는 "팀 없이 곡만 보기") → (팀장) PIN. 하단 메뉴(v0.5~): 오늘 / 곡 / 콘티 / 더보기. 팀·앱 관리·로그아웃은 더보기 안.

## 13. 다음 차수 요구사항 (사용자 요청, 2026-11-09 — 분류(주제)는 4차, 곡 이동·전체화면 상단 정보는 5차에서 구현 완료. 필기만 남음)
- (5차에서 구현 완료, 15장) **콘티 안에서 곡 이동**: 콘티에 곡이 여러 곡이면 화면 좌우 터치 또는 스와이프로 이전 곡/다음 곡으로 이동. (5차 연주 모드) — 이미지 악보 확대·스크롤(핀치)과 충돌하지 않게 설계해야 함.
- **전체화면 악보 + 상단 정보**: 악보를 전체화면으로 보더라도 콘티 항목의 **송폼·메모** 등이 상단에 보이게.
- **악보에 직접 메모(필기)**: 궁극적으로 악보 위에 직접 메모할 수 있는 기능. (후순위, 5차 이후 별도 차수 — 저장 범위(개인/팀)·아이패드 펜 사용·이미지/코드 악보 모두 지원할지는 착수 전에 합의)
- **분류(주제)**: 찬양, 경배, 회개&보혈, 예수님, 성령님, 교회&하나님나라, 결단, 선포, 성탄, 십자가&부활 등 — 4차(검색·태그)에서 구현 완료(14장).

## 14. 4차(검색·태그·이력)에서 확정된 사항 (v0.3)
- **주제 분류 방식 = 자유 태그 + 추천 칩**: 곡의 `tags`(쉼표 구분)는 그대로 자유 입력이고, 관리자가 정한 "추천 태그"가 곡 편집·곡 목록 필터·콘티 곡 추가 화면에 칩으로 나온다. 한 곡에 여러 태그(주제 여러 개) 허용. 새 칼럼은 없고, 추천 목록은 `settings.tag_presets`(JSON)에 저장. 기본값: **주제**(찬양, 경배, 회개&보혈, 예수님, 성령님, 교회&하나님나라, 결단, 선포, 십자가&부활) · **빠르기**(빠른곡, 느린곡) · **절기**(성탄, 고난주간, 부활절, 성령강림절, 추수감사절, 송구영신). 성탄은 처음 주제 초안에 있었으나 절기와 주제를 나누기 전에 적은 것이라 절기로 옮김(사용자 확정).
- **추천 목록 편집은 관리자만**: 분류 추가/삭제/이름 변경, 태그 추가/빼기. 곡에 쓰인 태그의 이름 바꾸기·합치기·모든 곡에서 지우기도 관리자 화면에서(추천 목록에도 함께 반영).
- **목록 필터**: 분류 안에서는 하나, 분류끼리는 "그리고"로 좁힌다(예: 경배 + 느린곡). 곡에 쓰이지 않는 추천 태그는 필터에서 숨기고, 추천에 없는 태그는 "기타"로 묶는다.
- **외부 검색 링크**: 검색어가 있으면 Google·YouTube·Ultimate Guitar 검색 페이지 링크를 보여 주고(편집 가능하면 "새 곡으로 등록"으로 제목 미리 채움), 곡 편집 화면에서도 제목 기준 링크 제공. 악보를 가져오는 기능은 없다(저작권).
- **최근 사용**: 우리 팀 콘티 기준, 오늘(한국 시간)까지의 콘티에서 마지막으로 쓴 날짜·횟수. 앞으로 잡힌 콘티는 "예정"으로 따로 표시. 곡 목록에 "최근 M/D"·정렬(제목순/오래 안 부른 순/최근 부른 순), 곡 화면에 사용 이력. 팀에 가입하지 않으면 표시 안 함.
- **수정 이력**: `song_versions` 한 줄 = 코드 악보 본문이 바뀌기 전 모습 + 고친 사람(관리자/팀). 곡마다 최근 50개만 보관. 화면(#/history/곡번호)에서 목록, 줄 단위 비교, 되돌리기(편집 권한자만). 되돌리기 직전의 본문도 이력에 남겨 다시 되돌릴 수 있다. 제목·태그·메모·이미지 변경은 이력에 없다.
- **API 추가**: `GET /api/tags` · `PUT /api/admin/tags` · `POST /api/admin/tags/rename` · `GET /api/songs/:id/versions` · `GET /api/songs/:id/versions/:vid` · `POST /api/songs/:id/versions/:vid/restore`. 곡 목록에 `last_used`·`use_count`, 곡 상세에 `usage` 추가. DB 표 변경 없음.

## 15. 5차(연주 모드·오프라인) 및 함께 요청한 검색 개선 (v0.4)
- **빠르기에 "중간곡" 추가**: 기본값 빠른곡·중간곡·느린곡. 관리자가 이미 저장한 추천 목록의 "빠르기" 분류에는 `settings.mid_tempo_added` 표시를 두고 **한 번만** 끼워 넣는다(이후 관리자가 지워도 되살리지 않음).
- **검색 규칙**: 띄어쓰기·기호·대소문자 무시(`searchKey`: NFC 정규화 → 소문자 → 글자·숫자 외 제거) 후 부분 일치. 검색어를 단어로 나눠 "이은 전체가 포함" 또는 "모든 단어가 포함(순서 무관)"이면 일치. 제목·원제·아티스트·태그가 맞으면 rank 0, 가사(본문 + 검색용 가사)로만 맞으면 rank 1로 뒤에 둔다. 가사로 맞은 곡은 `snippet {text,label}`(label: 후렴/가사/검색용 가사)을 돌려준다. 후렴 판별: `{soc}~{eoc}` 또는 `{comment: 후렴|코러스|chorus}` 바로 아래 한 덩어리(빈 줄에서 끝). 중복 제목 검사도 같은 규칙(띄어쓰기만 다른 제목은 중복).
- **원제**(`songs.orig_title`): 곡 편집·곡 보기·목록·콘티 곡 추가에 표시, 검색 대상. 선택 입력.
- **검색용 가사**(`songs.lyrics_extra`, 최대 3000자): 이미지·PDF 전용 곡의 후렴 등을 검색할 수 있게 직접 적어 두는 칸. 화면에는 보이지 않고 검색에만 쓰인다. 7차(이미지→코드)에서 자동 채우기 후보. 두 칸 모두 `ensureColumn()`으로 추가.
- **후렴 검색을 더 확장하는 방법(미구현, 후보)**: ① 7차 이미지→코드 변환 결과를 본문으로 저장하면 자동으로 검색됨 ② Cloudflare AI(OCR)로 이미지에서 글자를 뽑아 `lyrics_extra`에 채우기 ③ 곡 수가 수천 곡이 되어 느려지면 D1 FTS 검색 테이블 도입(현재는 곡 목록을 한 번 읽어 서버에서 비교).
- **연주 모드**(`#/play/콘티번호?i=순서|song=곡번호`, `#/play/song/곡번호`): 전체 화면. 하단 버튼·자동 스크롤·확대(lightbox)는 **없음**(사용자 요청: 악보를 최대한 크게, 스크롤 불필요, 확대 불필요). 위 한 줄(✕·곡 이름[탭=곡 목록]·오프라인 배지·⚙)과 그 아래 정보 줄(키·송폼·메모·코드↔이미지 전환), 나머지는 악보. 이미지 악보는 한 장씩 칸 안에 `contain`으로 통째로 맞춤(칸 높이 `--bodyh`를 JS로 측정). 좌우 스와이프(가로 60px 이상, 세로의 1.5배 이상, 0.8초 이내)·이미지 악보일 때 화면 양옆 14% 탭·키보드 화살표로 이동하고, 이미지가 여러 쪽이면 쪽을 먼저 넘긴 뒤 곡을 넘긴다(이전으로 갈 땐 이전 곡의 마지막 쪽). 아래 중앙에 "곡 n/N · 쪽 n/N" 작은 표시. 코드 악보는 세로 스크롤만(`touch-action: pan-y`, 가로 넘침 숨김). 키는 콘티 ▶ 기기 개인 키 ▶ 팀 기본 키 ▶ 원키. 설정(화면 색·화면 꺼짐 방지·코드 악보용 글자 크기/코드 표시/♯♭)은 기기별 localStorage(`ews_play_*`). 나가면(뒤로 가기 포함) `teardown()`으로 정리. 곡 보기의 확대 화면(`Files.lightbox`)도 처음엔 한 화면에 통째로 맞춤(z=0), 누르면 가로폭 기준 확대.
- **PWA·오프라인**: `manifest.webmanifest` + 아이콘, `sw.js`(서비스 워커). 앱 파일·곡/콘티/내 정보 API는 "인터넷 우선, 안 되면 저장본"(저장본으로 응답하면 `X-From-Cache: 1`을 붙여 "오프라인" 배지에 사용), 악보 이미지는 "저장본 우선"(최대 150장, 서명 `?s=` 무시). 곡·콘티 목록 검색·관리자·로그인 API는 저장하지 않는다. 콘티의 **오프라인 준비**가 그 콘티의 곡과 이미지를 미리 받아 둔다(PDF 제외). 로그아웃 시 `ews-data*`, `ews-img*` 저장소를 삭제.
- **필기(별도 차수)**: 여전히 미착수. 착수 전 합의 항목은 13장 그대로.

## 16. 5.5차 UI 개편 (v0.5)

- **메뉴**: 오늘(`#/`, 이번 주 콘티 카드 + ▶ 연주 + 곡 검색) · 곡(`#/songs`) · 콘티(`#/setlists`) · 더보기(`#/more`, 내 편집 권한·우리 팀·앱 관리·로그아웃). `#/team`, `#/admin`은 그대로 두고 더보기에서 들어간다. 관리자 탭은 없앴다.
- **권한은 필요한 순간에**: `lockBtn(kind, label, go)` — 권한이 있으면 보통 링크, 없지만 열 수 있으면 🔒 버튼(누르면 PIN 창 `askPin`), 열 방법이 없으면 숨김. kind=`leader`(콘티, 팀장 PIN) · `song`(악보, 관리자 PIN / 악보 권한 팀장 PIN). 성공하면 원래 가려던 화면으로 이동. 더보기에 "편집 권한 닫기"(이 기기의 관리자·팀장 열쇠 삭제).
- **곡 보기**: 악보 먼저, 키·카포·표기·글자 크기는 "키 G ▾" 아래 창(`#ksheet`), 편집·이력은 ⋯ 메뉴, ▶ 연주 모드는 큰 버튼.
- **연주 모드 보강**: 이미지는 CSS(`object-fit: contain`)로 칸에 맞춤(회전 안전), 가로 화면용 한 줄 상단, 다음 곡 미리보기.
- **디자인**: 상단 앱 이름 막대는 스크롤과 함께 올라감(고정 아님), 버튼 최소 높이 44px, 팀·관리자 화면의 부가 카드는 접이식, 용어 통일(콘티 편집=팀장, 악보 편집=관리자/허용된 팀장).
- **안전장치**: 화면을 옮기면 옛 화면이 보낸 요청의 응답은 버린다(`routeGen`) — 느린 옛 화면이 새 화면을 덮어쓰던 문제 방지.

## 17. 6차 — 송폼 탭 입력 + 내보내기 (v0.6)
**결정(사용자 확정)**: 카톡 텍스트는 **간단형(A)** — 곡마다 "n. 제목 (키)" 아래 줄에 `송폼:`·`메모:`. 이미지 악보 곡의 키는 따로 표시 없이 그냥 키로 적는다. PDF/이미지의 "교회 내부 사용 전용" 문구는 **넣지 않는다**(사용자 요청). 내보내기 범위는 콘티 단위(곡 하나만 내보내기는 미구현).

**송폼 탭 입력** (콘티 편집 화면, `public/songform.js` + `app.js`의 `formInner/formAction`)
- 저장 형식은 그대로 `setlist_items.form` 한 줄 글자(`인트로-V1-C-V2-C-B-C`, 최대 200자). DB·기존 API 변경 없음. 기존에 글자로 적은 송폼도 `SongForm.parse`(구분 `- – — → > ,` 공백, 괄호 안은 한 덩어리)로 칩으로 보인다. **사용자가 버튼을 누를 때만** 정규화되어 저장 문자열이 바뀐다(손대지 않은 송폼은 원문 유지).
- 구간 버튼: 인트로·V1·V2·V3·P·C·B·간주·태그·아웃트로·엔딩(+ 직접 입력). 쌓인 구간을 누르면 선택 → ◀▶ 이동·복제·`×반복`(×2→×3→×4→없음)·삭제, 선택이 있으면 새 구간은 그 뒤에 들어가고 선택이 새 구간을 따라간다. 카드별 되돌리기(최대 30단계, 저장되지 않음)·모두 지우기. 200자 초과는 거부(토스트).
- **지난번 송폼**: `GET /api/team/last-forms?exclude=<콘티번호>` → `{forms: {곡번호: 송폼}}`. 우리 팀 콘티 중 날짜가 가장 최근인 비어 있지 않은 송폼(현재 콘티 제외). 팀원이면 조회 가능, 다른 팀은 보이지 않음. 송폼이 비어 있는 카드에 "↺ 지난번 송폼 불러오기" 버튼.

**내보내기** (콘티 보기 화면, 팀원도 사용 가능. `public/export.js`는 누를 때만 불러옴)
- **카톡용 텍스트**: `SongForm.kakaoText`. 제목이 "콘티"로 끝나면 중복하지 않는다. 콘티 메모는 `※ `로 머리 아래에. 클립보드가 막히면 글자를 보여 주는 창으로 대체.
- **표지 이미지(PNG)**: 1080px 폭, 높이는 내용에 맞춤. 날짜·제목·메모·곡 순서·키·송폼·메모.
- **PDF**: A4(표지 → 곡 순서대로). 한글 글꼴을 PDF에 넣지 않으려고 **표지·코드 악보는 캔버스에 그려 JPEG 쪽으로** 넣고(글자 선택·검색은 안 됨), **이미지 악보는 원본을 가로/세로 쪽에 맞춰**, **PDF 악보는 쪽을 그대로 합친다**(`vendor/pdf-lib.min.js` v1.17.1, MIT, `PDFDocument.copyPages`). 곡마다 위쪽에 번호·제목·키·원키·BPM·송폼·메모. PDF 악보 곡은 안내 쪽(곡 정보) + 원본 쪽들.
  - 코드 악보: 콘티 항목의 키(없으면 팀 기본 키)로 이조(카포 없음, 표기는 앱 곡 화면과 같은 `Chord.plan/transposeChord`). 코드 위·가사 아래 정렬, 폭 초과 시 낱말 단위 줄바꿈(낱말 중간의 코드 때문에 낱말이 쪼개지지 않게), 후렴 막대, `{comment}`는 소제목. 한 곡이 2쪽을 넘으면 글자를 1 → 0.9 → 0.8 → 0.72배로 줄여 본다(하한).
  - 항목의 `view`(auto|chord|image)를 따르고, 선택한 쪽에 악보가 없으면 반대쪽으로, 둘 다 없으면 "등록된 악보가 없습니다" 안내 쪽.
  - 일부 곡·파일이 실패해도 멈추지 않고 안내 쪽으로 대체한 뒤 결과 창에 경고를 보여 준다.
  - 결과 창에서 **공유하기**(Web Share, 파일 공유 지원 시) · 저장 · 열어 보기. 만드는 데 오래 걸리면 브라우저가 공유를 막을 수 있어서 완료 후 새로 한 번 더 누르게 했다.
- 서비스 워커 앱 파일 목록에 `songform.js`·`export.js`·`vendor/pdf-lib.min.js` 추가(오프라인 앱 실행용). PDF 만들기는 곡·파일을 새로 받아야 하므로 인터넷 필요.
- **한계/후속 후보**: 곡 하나만 PDF로 내보내기, 곡별 이미지(PNG) 내보내기, 코드 악보를 글자(선택 가능)로 넣기(한글 글꼴 포함 필요), 쪽 번호.

## 18. 7차 — 코드 악보 입력 개선 (A단계, 2026-11-09)
사용자 결정(카드로 확인): 작업 기기 = 아이폰·아이패드·맥북 모두 / 원본 = 직접 듣고 만듦 + 글자 형식 자료 옮김 / **A 먼저, 이어서 B** / 이미지→코드 변환은 편집기 다음 차수 / 숫자(도수) 입력은 필요 없음. 제안서: `claude/코드악보-편집기-제안.md`.

**원칙**: 저장 형식은 ChordPro 글자 그대로(DB·서버·다른 화면 변경 없음, `functions` 수정 없음). 입력 화면(`viewEdit`)만 바뀐다.

**새 파일 `public/chordedit.js`** (`ChordEdit`, 브라우저·Node 양쪽, 화면과 무관한 순수 함수 — Node 단위 테스트 72항목)
- `diatonic(key)`: 곡 키의 기본 코드(장조 I IV V vi ii iii / 단조 i iv V VI VII III, 키에 맞는 ♯/♭ 표기). `bassNotes(key)`: 슬래시 베이스 후보(음계 7음).
- `chordAt(text,pos)` / `changeChord(inner,{quality|bass})`: 커서가 든 `[코드]`를 찾아 모양(m, 7, maj7, m7, sus4, add9, dim, 6, 장)이나 베이스만 바꾼다.
- `sectionEdit(text,a,b,name)`: 구간 버튼(인트로·1절·2절·3절·프리코러스·후렴·브릿지·간주·엔딩)이 글자를 어떻게 바꿀지 계산. 후렴은 `{comment: 후렴}`+`{soc}…{eoc}`, 줄을 선택하고 누르면 그 줄들을 감싼다. 앞줄이 비어 있지 않으면 빈 줄을 하나 넣는다.
- `check(text,key)`: 점검. **warn**(저장 전 확인창 대상): `[` 안 닫힘·짝 없는 `]`·빈 `[]`·이상한 코드 모양·`{soc}/{eoc}` 짝 불일치·`{ }` 모양 오류. **info**(참고만): 모르는 지시어(화면에 안 나옴)·코드 없음·첫/마지막 코드가 키 음계 밖. 코드 모양은 루트+품질+슬래시 베이스 정규식(`[?]`, `N.C.` 허용).

**화면** (곡 편집)
- 본문 위 버튼줄: 코드(키 기반) · 모양 · 구간 · (코드 안에 커서가 있으면) 베이스. 폰에서는 한 줄씩 옆으로 밀어 보고(화면의 절반을 차지하지 않게), 폭 900px 이상에서는 위에 고정된다. 선택한 글자는 지우지 않고 그 앞에 코드를 넣는다.

- 점검 패널(입력 후 0.5초): 줄 번호를 누르면 그 줄이 선택된다. 저장 때 warn이 있으면 한 번 확인창(막지는 않음).

**검증**: 단위 72 · 화면 36(버튼 삽입·모양·베이스·구간·되돌리기·점검·확인창·임시저장 복원/삭제) · 회귀 10(홈·곡·더보기·이력·편집·연주 로드, 열었다 저장해도 본문 불변). 실기기(아이폰 사파리 커서 위치, 가로 스크롤 줄 조작감)는 사용자 확인 필요.

## 19. 7차 — 코드 악보 입력 개선 (B단계, 2026-11-09)
사용자 결정(카드): A단계 사용 후기 = "괄호를 다 치는 것보다 낫지만 아직 익숙하지 않음 / 한 번 코드가 커서 자리에 안 들어가고 앞 코드에 계속 붙음 / **아이폰에서 가사 입력칸과 칩 사이를 위아래로 오르내리느라 시간이 걸림**". 글자 자료의 모양 = **가사만 있음**(윗줄 코드 변환은 필요 없어 보류). B단계 순서 = **탭 편집기 → 가사 붙여넣기 변환**.

**원칙 유지**: 저장 형식은 ChordPro 글자 그대로. `functions`·DB 변경 없음. `#cp` 글자 칸이 항상 진짜 내용이고, 탭 편집기는 그 글자를 읽어 고친 뒤 다시 써 넣는다(입력 이벤트를 발생시켜 미리보기·점검·임시저장이 그대로 동작).

**새 파일 `public/tabedit.js`** (`TabEdit`, 브라우저·Node 양쪽, 순수 함수 — Node 단위 테스트 68항목)
- **무손실 모델**: `parse(text)` → 줄 목록 `{kind: lyric|blank|comment|soc|eoc|other, raw, …}`. 가사 줄은 `{text, chords:[{pos,c}]}`(pos = 코드가 붙는 글자의 번호). `serialize`는 각 줄의 `raw`를 잇는다 — **손대지 않은 줄은 원문 그대로**, 고친 줄만 `lyricRaw`로 다시 만든다. 괄호가 깨진 줄·`#` 주석·모르는 지시어는 `other`로 그대로 보존(편집 불가, 글자로 보기에서 고침). 같은 자리의 코드는 들어간 순서를 지킨다.
- 편집 함수(모두 새 모델을 돌려줌, 원본 불변): `addChord`·`appendChord`(코드만 있는 줄 이어 붙이기)·`replaceChord`·`deleteChord`·`moveChord`(한 글자씩, 줄 끝에서 멈춤)·`reshape`(모양·베이스만 변경), `insertLines`·`replaceLine`·`deleteLine`·`clearChords`·`setLyricText`(코드가 앞·뒤 공통 글자를 기준으로 따라가고 고친 한가운데 코드는 고친 자리 앞으로), `insertSection`·`toggleChorus`(덩어리를 `{comment: 후렴}`+`{soc}…{eoc}`로 감싸기/풀기)·`isInChorus`.
- 가사 붙여넣기: `splitLyrics`(빈 줄 기준 덩어리, `[1절]`·`(후렴)`·`Verse 2` 같은 이름표 줄 인식, 같은 가사가 반복되면 후렴·나머지는 1절·2절… 추측, 가사 안의 `[ ]`·`{ }`는 제거) → `buildFromBlocks`(이름표·`{soc}` 포함 ChordPro 글자).

**화면** (`viewEdit`, 곡 편집 · 상단 스위치 "탭 편집 / 글자로 보기", 선택은 `ews_edit_mode`에 기억, 기본 탭 편집)
- 탭 편집: 가사를 코드 위·글자 아래 모양으로 표시(글자 22px, 글자마다 탭 영역). 글자 탭 = 그 글자 앞이 선택, 줄 끝 `＋` = 줄 끝, 얹은 코드 탭 = 코드 선택. 후렴은 왼쪽 선과 배경으로 표시.
- **하단 고정 팔레트**(`position: sticky`, 하단 메뉴 바로 위): ↶ ↷ · 상태 한 줄 · 키 기반 코드 칩 + `?` + 다른 코드… · (코드 선택 시) ◀ ▶ · 하나 더/이어 붙이기 · 코드 삭제 · 모양·베이스. A단계의 "위아래 오르내림" 불편을 없애려는 구조. 선택한 글자가 팔레트에 가려지면 화면을 자동으로 조금 올린다.
- 줄 메뉴(각 줄 왼쪽 ⋯, 아래에서 올라오는 창): 가사 고치기 · 후렴 표시 켜기/끄기 · 아래에 가사 줄 추가(여러 줄 붙여넣기 가능) · 코드만 있는 줄 추가 · 빈 줄 · 구간 이름 넣기/바꾸기 · 코드 지우기 · 줄 삭제.
- 가사 붙여넣기 창: 붙여넣기 → 구간 나누기 → 구간별 이름 선택 → 악보에 넣기(기존 본문이 있으면 뒤에 이어 붙임). 두 입력 방식 모두에서 쓸 수 있다.
- 되돌리기·다시: 탭 편집 안에서 60단계(글자로 보기로 바꾸면 초기화). 되돌린 뒤에는 선택이 풀린다.
- 서비스 워커 앱 파일 목록·`index.html`에 `tabedit.js` 추가. CSS는 `style.css` 끝 "7차 B단계" 블록.

**검증**: 단위 68(왕복 무손실 · 코드 넣기/바꾸기/지우기/옮기기 · 가사 고치기 · 구간·후렴 · 붙여넣기 분할) · 화면 37(폰 375px: 가사 붙여넣기→구간 확인→코드 얹기→이동·모양·베이스·교체·삭제·되돌리기·다시 · 줄 끝 코드 · 후렴 켜기/끄기 · 가사 고치기 · 코드만 있는 줄 이어 붙이기 · 다른 코드 창 · 모드 왕복 무변화 · 저장 · **주석·깨진 괄호가 섞인 옛 곡을 열고 모드를 오가도 본문 동일, 한 줄만 고치면 그 줄만 바뀜**) · 기기별 28(폰·아이패드·데스크톱·다크: 아래쪽 줄을 탭해도 선택한 코드가 팔레트에 안 가림, A단계 글자 모드 버튼 회귀). 실기기(아이폰 사파리 터치 정확도·스크롤 보정, 아이패드 펜 탭)는 사용자 확인 필요.

- **`loadMe` 반복**: `/me` 응답에 `team`이 없는데 활성 팀이 있으면(가입코드 재발급·팀 삭제) 그 항목을 `stale:true`로 표시하고 `ensureActive()`로 쓸 수 있는 다른 팀으로 넘어가 `/me`를 다시 부른다(최대 12회). `me.team`이 오면 활성 항목의 번호·이름·팀장 여부를 동기화하고, 같은 번호의 중복 줄을 정리한다.
- **오프라인 저장본 구분**: 서비스 워커의 `ews-data` 저장본은 주소 기준이라, `api()`가 **GET 요청에 `_t=<활성 팀 번호>`를 붙인다**(서버는 무시, `sw.js`는 pathname으로만 판별하므로 변경 없음). 팀이 다르면 저장본 키가 달라 오프라인에서 팀을 바꿔도 섞이지 않는다. 팀을 나가거나 목록에서 지울 때 `purgeTeamCache(id)`가 `_t=<id>` 저장본만 삭제. (임시 항목 번호 0은 `_t`를 붙이지 않음)
- **화면**: `teamChip()`(`.team-chip`, stale 팀이 있으면 빨간 점) → `openTeamSheet()`(`showSheet`, 팀 목록 + 보는 중/팀장/다시 입장 필요 표시, stale 팀은 "지우기", "+ 다른 팀 추가"). 칩은 오늘·콘티 목록 화면 위에, 더보기에는 "팀 전환 · 팀 추가" 줄, 팀 화면 위에는 "팀 전환 · 추가" 버튼. 팀 가입 화면은 `#/team?add=1`(다른 팀 추가, 건너뛰기 버튼 없음)과 `&re=<팀 이름>`(다시 입장 안내)을 지원(`viewTeam(q)`). **반복 구간 코드 복사 (`public/tabedit.js`, `app.js`)**
- 순수 함수(Node 단위 테스트 32항목): `lyricKey`(공백·기호·대소문자 무시, NFC), `findSameLyric(model, li)`(같은 가사 + 코드가 달린 가장 가까운 줄, 같은 거리면 위쪽), `copyLineChords(model, dst, src, {overwrite})`, `bodyBlocks(model)`(가사 덩어리 목록: `a,b,label,lines,chordLines,first`; 라벨은 바로 위 `{comment}`, `{soc}`는 건너뜀), `copyBlock(model, src, dst, {overwrite})`(k번째 줄 ↔ k번째 줄, 반환 `{model, filled, skipped, extra}`).

- `style.css`: `.teambar`, `.team-chip`(`.dot`), `.team-row`, `.team-pick`, `.chk-row`.

### 23-3. 악보 위 필기 — 설계(안, 구현 전, 사용자 합의 2026-11-10)
**합의된 요구**
- 대상: 이미지 악보가 주, 코드 악보도 필요. 필기는 **콘티용 필기**와 **곡 기본(공통) 필기** 두 종류.
- 코드 악보는 **연주 때 2단 보기가 기본**이므로 1단/2단·글자 크기·키가 바뀌어도 필기가 어긋나지 않아야 한다.
- 저장: **기본은 내 기기에만**, 팀장이 **특정 필기를 골라 팀에 공유**할 수 있다.
- 기기: 아이패드 + Apple Pencil 중심. Pencil이 없는 기기에서는 **텍스트(붙여넣기 포함)** 로 대체.
- 기능: 펜(색·굵기), 형광펜, 지우개, 되돌리기/다시하기, 텍스트.

**핵심 설계**
1. 필기 데이터는 픽셀이 아니라 **악보 안의 위치(앵커)** 로 저장한다.
   - 이미지·PDF 쪽: 그 쪽 그림의 가로·세로를 0~1로 정규화한 좌표. 화면 크기·확대·회전과 무관.
   - 코드 악보: **줄 앵커**. 각 획을 가장 가까운 악보 줄(본문의 줄 번호 + 가사 글자 해시)에 붙이고, 좌표는 그 줄 상자 안의 비율(가로 0~1, 세로는 줄 높이 배수, 위아래 ±2줄까지 허용해 줄 사이 여백에도 쓸 수 있음)로 저장. 1단↔2단, 글자 크기, 키 변경(코드 글자 폭이 달라져도 가사 줄 상자는 유지)에서 같은 줄에 붙어 있다. 곡 본문을 고치면 가사 해시로 줄을 다시 찾고, 못 찾으면 "위치를 잃은 필기" 목록으로 보여 준다.
   - 텍스트 메모도 같은 앵커(줄 또는 이미지 좌표)에 붙는다.
   - 코드 글자 위에 동그라미 같은 **코드 전용 표시**는 키 변경 시 의미가 달라질 수 있어, 이번 설계에서는 "줄 앵커 필기"로만 다루고 코드 앵커는 별도 요청이 있을 때 검토.
2. **저장 위치와 공유**
   - 개인 필기: 이 기기의 IndexedDB(서버 변경 없음, 기기를 바꾸면 안 보임 — 합의된 동작). 곡·콘티 삭제 시 정리 필요.
   - 팀 공유: 팀장이 "공유할 필기"를 골라 올리면 서버 새 표 `annotations`(team_id, scope, song_id, item_uid, page_ref, data JSON, updated_at)에 저장, 팀원은 읽기 전용 겹침 층으로 보며 켜고 끌 수 있다. 새 칸·표는 `ensureColumn`/`CREATE TABLE IF NOT EXISTS`로만 추가(운영 DB 보호).
3. **콘티용 필기에는 항목의 고정 번호가 필요하다.** 지금 콘티 저장(`PUT /api/setlists/:id`)은 항목을 통째로 지웠다 다시 넣어 `setlist_items.id`가 매번 바뀐다. 그래서 `setlist_items.uid`(문자열, `ensureColumn`)를 새로 두고 화면이 항목마다 같은 `uid`를 유지해 보내도록 바꿔야 한다. 곡 순서를 바꿔도 필기가 그 곡 항목에 따라간다.
4. **입력 방식**
   - Apple Pencil(`pointerType==='pen'`)은 쓰기, 손가락은 스크롤·확대·넘기기(이번 차수에서 슬라이드 넘기기는 이미 스타일러스를 무시). "손가락으로도 쓰기" 켜기 옵션. 아이패드의 "Apple Pencil로만 그리기" 설정과의 상호작용은 실기기 확인 필요.
   - 획은 점 목록으로 받아 단순화(Douglas-Peucker)해 저장 크기를 줄이고, SVG 겹침 층으로 그린다. 형광펜은 반투명 `multiply`. 지우개는 획 단위 지우기.
   - 연주 모드에서는 상단의 "✎ 필기" 켜기/끄기로 전환(끄면 보기·넘기기 전용).
5. **내보내기**: 6차 PDF·표지 이미지에 필기를 포함할지는 구현 시 결정(기본: 포함하지 않음, 옵션 제안).

**제안 단계** (각 단계마다 따로 배포·확인)

### 25-2. 연주 모드 쪽 넘기기 (24-2b)
- `chord.js renderHTML(..., {parts:true})`: 구간(구간 이름 줄부터 다음 구간 이름 직전, 이름 없이 시작하는 후렴은 그 블록)을 `<div class="part">`로 묶는다. 연주 모드만 켠다. 단 나누기(`.colb`)는 구간 바깥에 둔다.
- `fitCols(body, varEl, wantPage)`(app.js): 높이를 고정한 다단(`column-fill:auto`, `column-width`)으로 깔고 `translate3d`로 쪽을 민다. 화면에 보이는 단 수 v = 좁으면(폭 700px 미만 또는 설정 1단) 1, 넓으면 2.
  - v=2: 먼저 글자를 최소 14px까지 줄여 **한 쪽에 다 들어가는지** 본다(예전과 같은 결과). 안 되면 설정한 글자 크기로 돌아가 `keepparts`(구간 안 끊기)로 여러 쪽으로 나눈다.
  - v=1(아이폰): 글자를 줄이지 않고 설정 크기대로 쪽을 나눈다.
  - 쪽 이동 거리 step = v × (단 너비 + 36px). 결과는 `.score` 의 `data-step/page/pages`, 반환값 `{pages,page,step,v}`.
- 이동: `target(d)`가 이미지 쪽과 같은 규칙으로 코드 쪽도 다룬다(쪽 → 곡). 이웃 쪽·곡은 10차의 ghost 슬라이드를 그대로 쓴다(`makeGhost`가 같은 `fitCols`로 이웃을 맞춤). 이전 곡으로 가면 그 곡의 **마지막 쪽**. 점 표시는 "곡 n/N · 쪽 n/N", 쪽이 2개 이상이면 양옆 탭 영역이 켜진다. `#pnext`(다음 곡 미리보기)는 쪽이 여러 개면 바로 다음 곡으로.
- 다시 그릴 때 위치 유지: 글자 크기·표기·회전·창 크기 변경 때 지금 쪽 맨 앞 줄(`anchorOf`)을 기억했다가 같은 줄이 있는 쪽(`pageOfAnchor`)으로 돌아온다.
- 설정 ⚙ "긴 악보: 쪽 넘기기 / 세로 스크롤"(`ews_play_pages`, 기본 쪽 넘기기). 세로 스크롤은 9-B차 방식(2단 한 화면 맞춤, 안 되면 1단) 그대로.

서버 변경 있음(박자 검증, 콘티 응답에 박자) — **`functions`와 `public` 둘 다 올려야 한다.** 새 파일 없음. 연주 모드 쪽 넘기기는 건드리지 않았다.

### 26-1. 사용자 결정(2026-11-10, 카드)
- 13차 실기기: 쪽 넘기기는 기대만큼 효과가 크지 않음(예: 1절 뒤에만 후렴을 적어 두고 2절 이후엔 앞의 후렴을 다시 보는 식으로 쓰는데, 3·4절로 넘어가면 후렴으로 한 번에 돌아올 수 없음). **일단 수정하지 않고 그대로 둔다.** 저장소 지속은 "무엇을 확인해야 하는지" 모르겠다고 함(안내 필요). 나머지는 잘 동작.

- 원키와 팀 키가 다르면 **팀 키로 보이고 작은 원키를 병기**("원키 G").
- 키 필터·키순 정렬(8차)은 **팀 키 기준**으로 변경(팀 키가 없으면 원키).
- 박자는 **한 곡에 여러 개**(예: 3/4 곡을 4/4로 부를 때도 있음) 기입 가능.

### 26-2. 박자 여러 개
- `songs.time_sig`는 그대로 TEXT, 값만 `"3/4,4/4"`처럼 쉼표로 이은 형태(기존 단일 값은 그대로 유효). 서버 `cleanSong`이 항목별로 검증(분자 1~16 / 분모 2·4·8·16), 잘못된 항목은 버리고, 중복은 한 번만, **최대 4개**, 적은 순서 유지.
- 곡 편집: 박자 칩을 여러 개 켤 수 있고(다시 누르면 해제, 5번째는 안내 후 막음), "기타" 칸에는 `5/4, 7/8`처럼 쉼표로 여러 개. 기타 칸을 비우면 직접 쓴 박자만 해제.
- 표시는 `3/4 · 4/4`(맨 앞이 먼저 적은 박자). 내보내기 부제는 `3/4, 4/4`.

### 26-3. 표시 규칙 (`songfilter.js`의 `keyTsigHTML` 공용)
- 키 배지 = 팀 키가 있으면 팀 키, 없으면 원키. 바로 오른쪽에 박자 배지. 팀 키와 원키가 다를 때만(A#=Bb처럼 표기만 다르면 같은 키) 끝에 작은 `원키 G`. 키·박자가 없으면 아무것도 그리지 않음.
- 곡 목록 줄·곡 고르는 창: `keyTsigHTML`. 곡 고르는 창의 별도 "우리 팀 ○" 글자는 없앴다.
- 곡 보기: `#keymeta` 한 덩어리 = `우리 팀 [A]` + 박자 + `원키 G`(다를 때). 팀 키가 없으면 `원키 [G](추정)` + 박자. 팀 키를 저장하면 이 덩어리를 바로 다시 그린다(`refreshKeyMeta`).
- 오늘 화면 미니 콘티·콘티 보기 줄: 콘티에 적힌 키 옆에 박자(콘티 응답에 `time_sig` 추가). 연주 모드 정보 줄은 기존 위치(키 바로 옆)에서 여러 박자만 `·`로 표시.

### 26-4. 키 필터·정렬
- `SongFilter.effKey(s)` = 정규화한 팀 키, 없으면 정규화한 원키. 키 칩(곡 수 포함)·필터·키순 정렬이 모두 이 값을 쓴다. 칩 이름은 "키 (팀 키 기준)". 주소의 `key=`·`sort=key` 형식은 그대로.

### 26-5. 검증
- 서버: `"3/4, 4/4"`→`3/4,4/4`, 잘못된 항목·중복 제거, 4개 제한 확인. 단위: 표시 규칙·필터·정렬(키 없음 맨 끝). 브라우저(폰 크기): 목록·곡 보기·팀 키 저장 직후 갱신·미니 콘티·콘티 보기·곡 고르는 창·편집 칩·연주 모드 정보 줄·필터·정렬, 페이지 오류 0.

- 이번 차수: 이미지 악보 위 **개인 필기**(곡 기본 필기). 콘티용 필기·코드 악보 필기·팀 공유는 이번에 안 함.
- 기기: **아이패드 + 애플펜슬**, 아이폰은 손가락. 맥북은 필기 용도로 쓰지 않음(마우스도 쓰기는 됨).
- 저장: 23-3의 "이 기기에만 저장"을 **"개인 보관함 코드로 기기 간 동기화"로 변경.**

### 27-2. 데이터와 저장
- 필기는 **이미지 한 장(`song_files.id`)당 한 덩어리**: `{v:1, items:[…], del:[…]}`. 좌표는 그 그림의 가로·세로를 0~10000으로 나눈 정수 → 화면 크기·확대·회전과 무관.
  - 획 `{id,t:'s'|'h',c:'#RRGGBB',w:가로폭 만분율,p:[x,y,x,y…]}` (점은 Douglas-Peucker로 줄여 저장), 글자 `{id,t:'x',x,y,c,z:글자크기 만분율,s:내용}`. `del`은 지운 항목 번호(기기 간 병합 때 되살아나지 않게).
- **이 기기**: IndexedDB `ews-ink`/`pages`(`{fileId,songId,rev,data,dirty,stamp}`). 먼저 여기에 저장하고(인터넷 없어도 씀), 보관함이 연결돼 있으면 서버로 올린다. 서버에 아직 못 올린 장은 `dirty`로 남아 인터넷이 되면(`online`·앱 시작·저장 직후) 자동으로 올라간다.
- **서버(새 표)**: `vaults(id, code_hash UNIQUE, created_at, last_seen)`, `vault_items(vault_id, kind='ink', song_id, file_id, rev, data JSON, updated_at; UNIQUE(vault_id,kind,file_id))`. 모두 `CREATE TABLE IF NOT EXISTS`로만 추가(운영 DB 보호). 이미지 삭제·곡 삭제 때 해당 필기도 함께 지운다.
- 장당 필기 최대 400KB·3000개, 보관함당 1500장. 서버 `cleanInk`가 허용된 모양만 남긴다(좌표 0~10000으로 자름, 색은 #RRGGBB만).
- **병합**: 올릴 때 `base_rev`가 서버 `rev`와 다르면(다른 기기가 먼저 저장) 서버가 `mergeInk`(양쪽 항목의 합집합 − `del`, 같은 번호는 새로 온 것)로 합쳐 돌려준다. 같으면 올린 것으로 교체.

### 27-3. 개인 보관함
- 코드 12자(31글자 중, 4자씩 `ABCD-EFGH-JKMN`로 표시). **서버에는 SHA-256 해시만** 저장, 코드는 만든 기기에서만 다시 볼 수 있다(더보기). 로그인 후에만 쓸 수 있다(교회 접속암호 + 보관함 토큰 `X-Vault-Token`).
- 코드로 연결(`POST /api/vault/join`)은 틀리면 5회 후 10분 잠금(`auth_fails`, 키 `vault-join`). 토큰은 400일, 교회 접속암호를 바꾸면 무효(코드로 다시 연결하면 됨).
- API: `POST /api/vault`(만들기) · `POST /api/vault/join {code}` · `GET /api/vault/me` · `GET /api/vault/ink?song=ID`(생략하면 전부, 최대 400장) · `PUT /api/vault/ink/:fileId {song_id, base_rev, data}` · `DELETE /api/vault`(보관함과 서버의 필기 모두 삭제).
- 화면(더보기 > 내 필기 보관함): 만들기 / 코드로 연결 / 코드 복사 / 지금 맞추기 / 이 기기 연결 해제 / 보관함 지우기. 연결하면 서버의 필기를 받아 이 기기 것과 합치고, 이 기기에 쌓인 필기는 모두 올린다. **로그아웃하면 이 기기의 필기·보관함 연결도 지운다**(공용 기기 보호; 서버 필기는 코드로 다시 받을 수 있음).

### 27-4. 화면
- **곡 보기**: 이미지 악보 탭에 `✎ 필기하기` 버튼, 이미지 위에 내 필기가 겹쳐 보인다(보기만, 클릭은 기존대로 확대).
- **연주 모드**: 이미지 악보를 보고 있을 때 위쪽에 `✎` 버튼 → 같은 필기 화면. 이미지 위에 필기가 겹쳐 보인다. (슬라이드로 넘기는 중인 이웃 곡 미리보기에는 필기가 아직 안 보이고 넘어간 뒤 나타난다.)
- **필기 화면**(`Ink.edit`, 전체 화면): 위쪽 `완료 · 곡 제목 n/N · ‹ › − +`(장 이동·확대 1~4배), 아래쪽 도구 줄 `펜·형광펜·지우개·글자·이동 | ↶ ↷`와 색·굵기·`☝ 손가락 켬/끔`. 글자 메모는 빈 곳을 누르면 입력창, 글자를 누르면 고치기/지우기. 지우개는 문지른 획을 하나씩 지운다(되돌리기 가능). 1~4배 확대에서 `✋ 이동`으로 손가락 이동·확대.
- **손가락/펜**: 기본은 손가락으로도 쓰기(아이폰). 애플펜슬(`pointerType==='pen'`)이 처음 감지되면 손가락 쓰기를 자동으로 끈다(손바닥·확대 제스처와 겹치지 않게; ☝로 다시 켤 수 있고, 한 번 직접 바꾸면 자동으로 안 바꾼다). 손가락 쓰기가 꺼져 있을 때는 펜슬 획이 화면을 스크롤하지 않도록 Safari의 `touchType==='stylus'` touchstart를 막는다.
- **PDF 악보에는 쓸 수 없다**(PDF는 앱이 화면 안에 그리지 않고 열기 링크만 있음). 이미지로 올린 악보만 가능.

### 27-7. 15차 보완 — 아이패드 실기기 피드백 반영 (v0.15b, 2026-11-10, `public`만 바뀜: `ink.js`·`style.css`)
- **사용자 피드백(실기기)**: 보관함 코드 연결·필기 동기화 잘 됨, 아이폰에서 쓰기 편함, 펜슬로 선이 잘 그려지고 손가락 스크롤·확대도 됨. 문제 6가지: ① 펜슬로 쓰다 **중간에 끊김** ② 확대하면 **도구 줄이 안 보임** ③ **아이폰·펜슬 모두 이동이 안 되고 확대가 브라우저 화면 전체 확대**로 동작 ④ 글자 메모는 **탭한 자리 표시가 없고** 확인을 눌러야 보임 ⑤ **펜슬 모드에서 글자 입력창이 아예 안 뜸** ⑥ 필기 화면에 **완료만 있고 취소가 없음**.
- **원인과 고침**: ①③⑤는 브라우저의 기본 스크롤·확대(`touch-action: pan…`)에 맡긴 것이 원인(펜슬 획이 스크롤로 넘어가며 `pointercancel`→끊김·탭 무시, 두 손가락 확대는 페이지 전체 확대). → **필기 화면 안의 확대·이동을 직접 처리**하도록 바꿈: 화면 전체에 `touch-action:none`, 사파리 `gesturestart` 막기, 확대는 그림(`.ink-stage`)에 `transform: translate·scale`을 걸고 두 손가락 핀치·한 손가락 끌기·휠·`+ −`·라벨 탭(맞추기)으로 조작(1~6배). 그래서 ②(확대해도 도구 줄·위 줄은 그대로 고정)도 해결.
  - **입력 규칙**: 펜슬·마우스 = 쓰기. 손가락 한 개 = 쓰기(`☝ 손가락 쓰기`) 또는 이동(`☝ 손가락 이동`, 펜슬이 처음 감지되면 자동으로 이동으로 바뀜). 손가락 두 개 = 항상 확대·이동(쓰던 획은 버림). 펜으로 쓰는 중 닿은 손바닥은 무시. `✋ 이동` 도구는 모든 입력으로 화면 이동. 펜 입력이 `pointercancel`로 끊겨도 그은 데까지는 저장한다(손가락 입력은 취소 시 버림).
  - **확대해서 쓰면** 선 굵기·글자 크기·지우개 범위·점 단순화 기준을 확대 배율로 나눠, **화면에서 보이는 굵기가 같게** 저장한다(작은 글씨를 쓰기 쉽게). 서버 최소값(굵기 10, 글자 60) 이하로는 안 내려간다.
  - ④: 글자를 넣을 자리에 **점선 원+십자 표시**, 입력하는 대로 **실시간 미리보기**, 글자 색·크기도 바로 반영. 입력창이 가리지 않게 화면을 위로 옮기고(`revealPoint`), 키보드가 올라오면 `visualViewport`에 맞춰 필기 화면 높이를 줄인다. 글자 메모는 이제 확대 배율에 맞춰 크기가 정해진다.
  - ⑥: 위쪽에 **`취소`**(이번에 쓴 필기를 모두 버리고 닫기, 쓴 게 있으면 확인창) 추가. 필기 화면을 연 뒤 처음 불러온 장의 모습을 보관했다가 되돌린다(여러 장을 넘겨도 모두). `완료`는 저장 후 닫기, Esc도 완료.
- **검증**: CDP로 펜(`pointerType:'pen'`)·터치(핀치·한 손가락 끌기) 입력을 만들어 확인 — 펜 획, 펜 감지 후 손가락 이동 전환, 한 손가락 끌기 때 선 안 생김, 핀치 확대·페이지 확대 안 됨(`visualViewport.scale==1`)·도구 줄 유지, 확대 상태 펜 쓰기, 펜슬 글자 탭 → 표시·미리보기·입력창이 표시를 안 가림, 글자 취소, `취소`가 새로 쓴 것만 버리고 이전 필기는 유지, `완료` 저장(17항목) + 기존 UI 22항목 + 스모크 페이지 오류 0. 크롬(에뮬레이션) 검증이며 **실기기 사파리·애플펜슬 재확인 필요**.

### 27-8. 15차 재보완 — 아이패드 2차 피드백 (v0.15c, 2026-11-10, `public`만 바뀜: `ink.js`·`style.css`)
- **피드백**: ① 펜·형광펜이 여전히 끊김(스크린샷: 형광펜 호가 토막토막) ② 펜슬로 글자 메모를 만들려고 탭하면 잘 안 생겨서 손가락 쓰기로 바꿔 씀 ③ 최대 확대에서 글자 메모를 만들면 가장 작은 글씨로 써지는데, 글자 크기 버튼을 누르면 그보다 커짐(버그 의심) ④ 입력창에서 펜슬 손글씨(스크리블)로 쓰면 글씨가 안 사라지고 입력도 안 되며 버튼도 안 눌림.
- **고침(원인은 추정이며 실기기 재확인 필요)**:
  - ③ **버그 맞음**: 새 글자는 `크기÷확대배율`로 만들었는데 입력창의 크기 버튼은 배율을 무시하고 절대 크기를 넣었다. 이제 버튼도 `zFor(i)`(배율 반영)를 쓰고, "켜진 버튼"도 현재 크기에 가장 가까운 것으로 표시한다. 고른 크기는 다음 글자에도 기억된다.
  - ① 확대를 `transform: scale`(+`will-change`)로 하던 것을 **그림의 실제 크기를 바꾸는 방식**으로 교체(큰 레이어가 사파리에서 흐리게·조각나게 그려지던 문제 의심). 형광펜의 `mix-blend-mode: multiply`는 빼고 투명도 .42로. 그리는 중인 선은 화면 한 번 그릴 때마다 한 번만 갱신(`requestAnimationFrame`), 그림 위치 계산은 이벤트 묶음당 1회. **펜슬을 뗐다가 110ms 안에 그 끝에서 다시 대면 한 획으로 잇는다**(펜 입력이 잠깐 끊겨 두 획으로 갈라지는 경우 대비).
  - ②④ 탭 직후 브라우저가 보내는 **뒤따르는 클릭**이 방금 뜬 입력창의 버튼(취소 등)을 누르는 문제 의심 → 입력창을 연 뒤 450ms는 클릭을 받지 않게 했다. 도구 줄·입력창에는 `touch-action:none`을 걸지 않고(**그림 영역에만** 적용) 펜슬 손글씨와 버튼 탭을 방해하지 않게 했다. 포인터 캡처는 뗄 때 명시적으로 풀고(`releasePointerCapture`), 캡처가 풀리면 진행 중 동작을 마무리한다. 입력창이 떠 있는 동안 그림을 탭하면 글자 자리만 옮긴다(새 글자일 때).
- **검증**: 기존 UI 22 + 펜/터치 17 + 신규 9항목(확대는 크기 변경·CSS scale 없음, 끊긴 획 잇기·떨어진 획은 별도, 최대 확대에서 기본과 버튼 글자 크기 동일, 입력창 아래쪽 탭 뒤에도 유지, 탭하면 자리만 이동). 크롬 에뮬레이션이라 **스크리블·사파리 렌더링은 실기기 확인 필요.**


### 27-9. 15d — 펜슬 전용 문제 진단 (2차 피드백 후)
- 증상: 손가락으로는 안 끊기고 펜슬로만 끊김, 펜슬 탭으로는 글자 위치 표시가 안 생김(입력창·크기는 정상).
- 원인 미확정. 펜슬 입력이 중간에 `pointercancel`로 끊기는지 확인하려고 **필기 진단**을 추가(더보기 → 내 필기 보관함 → "필기 진단 켜기"). 필기 화면 왼쪽 아래에 pointerdown/up/cancel/lostpointercapture/touch*/click 순서와 이동 간격(>60ms) 횟수를 표시.
- 대응: 펜이 cancel로 끝난 획은 700ms 안에 0.06 거리 안에서 다시 시작하면 한 획으로 이어 붙임(정상 종료는 기존 110ms·0.02).
- 진단 결과(실기기): 펜슬 입력에 `pointercancel` 없음, 이동 끊김(>60ms) 0회 → 이벤트 도착은 정상. 펜 탭도 down/up이 150ms로 정상 도착하는데 글자 위치가 안 생김 → 처리 쪽 문제로 판단.
- 15d 수정: ① 펜이 닿기 전 공중(호버) 위치가 coalesced 이벤트로 묶여 와 점으로 들어가는 것을 거름(`e.buttons && !ev.buttons`) ② 탭 판정을 이동 누적거리가 아니라 처음 자리에서 가장 멀어진 거리로 ③ 진단에 `finish 도구 이동 점` 줄 추가.
- 15f(실기기 캡처 근거): 펜슬로 그은 선 위에 선과 수직인 하얀 틈이 일정 간격으로 보임. 입력은 정상(취소 0, 끊김 0, 점 428개)이라 **그리기 문제**로 판단. 사파리가 점이 많은 곡선 `stroke`에 틈을 내는 것으로 추정 → 획을 stroke 대신 **채운 모양(fill)** 으로 그림(`strokeD`: 곡선을 잘게 나눈 선분마다 직사각형+양끝 원을 한 path에 담음, nonzero). 형광펜은 `fill-opacity .42`(한 path라 겹쳐도 진해지지 않음, 끝은 둥글어짐). 데이터 형식은 그대로(`{t,c,w,p}`)라 서버·기존 필기 영향 없음.
- 펜슬 탭(글자 위치)은 아직 미확인: 이번 캡처에는 화면 탭 기록이 없었음(툴바 버튼만 눌림).
- 15g(실기기 확인 후): 펜 끊김·글자 입력 모두 정상 확인. 남은 증상: 펜슬로 입력창에 쓰기 시작할 때(스크리블 도구 막대가 올라오며 화면이 줄 때) 뒤의 앱 아래 탭이 잠깐 비침 → 필기 화면이 열려 있는 동안 `body.ink-open`으로 아래 탭(.nav)을 숨기고 배경을 어둡게.

## 28. 16차 (2026-11-10)

`public`만 바뀐다(서버·DB 변경 없음). 16A + 16B를 한 번에 커밋한다.

### 28-1. 아래 메뉴 밑 빈 띠 보정 (16A)
- 증상: 아이패드 홈 화면 앱에서 어떤 화면은 아래 메뉴 밑에 약 32px 배경색 띠가 보임. 메뉴(`position:fixed; bottom:0`)가 보이는 화면 맨 아래보다 위에 떠 있는 상태.
- 원인(실기기 진단으로 확인, 2026-11-10 21:44): 띠가 생긴 화면은 창 높이(`innerHeight`)와 보이는 영역(`visualViewport`)이 둘 다 992로, 실제 화면 높이 1024보다 안전영역 위쪽(상태 막대) 높이 32px만큼 짧음. 띠가 없는 화면은 창 높이 1024. 아래 메뉴(`fixed; bottom:0`)가 짧아진 창 맨 아래에 붙어 그 밑에 배경이 비침. 두 상태를 오가는 조건(짧은 화면일 때 등)은 아직 모름. 크롬 에뮬레이션으로는 재현되지 않음.
- 고침: `app.js fitNav()`가 남는 틈을 구해 `--nav-gap`으로 두고, `style.css .nav`가 `bottom:-gap` + `padding-bottom:+gap`으로 흰 배경을 아래로 늘림(글자·아이콘 위치 불변). 틈은 ① 보이는 영역 아래끝 − 메뉴 아래끝(16A), ② 홈 화면 앱에서 `화면 높이(세로=긴 쪽) − innerHeight`가 2~64px이고 안전영역 위쪽 높이와 ±4 이내면 그 값(16C, 위 진단 상황). 홈 앱이 아니면 ②는 안 씀(브라우저·창 모드 오판 방지). 다시 재는 때: `resize`·`orientationchange`·`pageshow`·`focusout`·`hashchange`·`visibilitychange`·`visualViewport resize`(+120·450·1200ms 뒤 재측정). 필기 화면이 열린 동안은 보정 안 함. **②로 메뉴를 창 밖(아래 32px)까지 늘려 그리는 것이 사파리에서 실제로 보이는지는 실기기 확인 필요.**
- 재보정 결과(22:02 실기기 캡처): `--nav-gap`이 32로 잡히고 메뉴 아래끝도 1024가 됐지만 **띠는 그대로** — 사파리는 창(992) 밖 32px에는 웹 화면을 그리지 않고 페이지 바탕색만 칠한다. 그래서 메뉴를 늘리는 방식은 효과 없음(코드는 무해해서 남김).
- 재재보정(`style.css` 끝, 16차 재보정(2)): ① `html { background: var(--card) }` — 창 밖 영역의 바탕색을 아래 메뉴 색과 같게 해 메뉴가 이어진 것처럼 보이게 함(`body`는 `min-height:100vh`로 자기 배경 유지, 필기 화면이 열리면 `html:has(body.ink-open)`로 어두운 바탕). ② `@media (display-mode: standalone) { main { min-height: calc(100vh - 20px) } }` — 홈 앱에서 문서가 창보다 살짝 길어지게 해, 짧은 문서(오늘·곡·콘티 목록)에서만 창이 992로 줄고 긴 문서(더보기)에서는 1024였던 상관을 이용해 창 줄어듦 자체를 피해 봄(가설, 실기기 확인 필요). 크롬에서 ②는 비홈앱이라 적용 안 됨을 확인하고, 규칙을 강제 적용해 문서가 창보다 15px 길어지는 것을 확인.
- 진단: 더보기 맨 아래 `화면 진단 켜기`(`ews_view_dbg`) — 창·보이는 영역·화면·메뉴 아래끝·남은 틈·보정 값(근거)·창이 짧은 정도·안전영역을 왼쪽 위에 표시.

## 29. 17차(16C) — 콘티용 필기 (v0.17, 2026-11-10)
콘티의 곡 한 칸마다 그 콘티에서만 보이는 필기를 따로 둔다. 곡 자체의 "기본 필기"는 그대로이고, 콘티에서 열면 기본 필기 위에 콘티용 필기가 겹쳐 보인다.

### 29-1. 결정
- 콘티에서 곡을 열면(연주 모드·곡 보기) 기본 필기 + 콘티용 필기가 함께 보임. 이때 ✎는 **콘티용**에 저장(곡 보기 버튼은 "✎ 콘티용 필기하기"). 곡을 단독으로 열면 지금처럼 기본 필기.
- 필기 화면(콘티용)에서는 기본 필기가 밑에 깔려 보이되 지우거나 고칠 수 없음.
- 지난 콘티를 **복사하면 콘티용 필기는 따라오지 않음**(새 곡 칸 번호). 다른 콘티에서 곡 "가져오기"도 마찬가지.
- 같은 곡이 한 콘티에 두 번 들어 있어도 칸마다 따로 필기됨.

### 29-2. 서버 (`functions/api/[[path]].js`)
- `setlist_items.uid`(TEXT, 12자리 16진수) 추가(`ensureColumn`). 예전 콘티는 **콘티를 처음 열 때(GET)** 칸마다 채움. GET 응답 `items[].uid`.
- POST(새 콘티·복사): 항상 새 uid. PUT(수정): 클라이언트가 보낸 uid가 **그 콘티에 이미 있던 것**이고 중복이 아니면 유지, 아니면 새로 부여. PUT은 항목을 지웠다 다시 넣지만 uid를 이어 가므로 필기가 유지됨.
- 새 표 `vault_sl_items(vault_id, uid, setlist_id, song_id, file_id, rev, data, updated_at, UNIQUE(vault_id,uid,file_id))`.
- `GET /api/vault/ink-sl?setlist=ID`(없으면 전체, 최대 800). `PUT /api/vault/ink-sl/:uid/:fileId` — 규칙은 기본 필기(`/vault/ink`)와 같음(`base_rev` 다르면 `mergeInk`, 크기 제한, 장 수 제한 `MAX_VAULT_PAGES`는 기본+콘티용 합산). 그 팀의 콘티 칸이고 그 곡의 이미지 파일일 때만 허용(아니면 404). `vault/me`에 `slPages` 추가.
- 정리: 콘티 수정으로 빠진 칸 · 콘티 삭제(단건·여러 개) · 팀 삭제 · 곡 삭제 · 파일 삭제 · 보관함 삭제 때 해당 콘티용 필기도 삭제.

### 29-3. 앱
- `ink.js`: 같은 IndexedDB 저장소에 문자열 키 `sl:<uid>:<fileId>`로 저장(레코드에 `sl, fid, setlistId`). `save(key, songId, data, meta)`, `pullSetlist(setlistId)`, flush·adoptServerNotes가 콘티용 레코드도 처리. `attachImg/decorate(…, sl)`은 기본→콘티용 순으로 한 SVG에 겹쳐 그림. `edit({…, sl:{uid,setlistId}})`는 저장 키만 바꾸고 기본 필기를 `.ink-under`로 깖(되돌리기·취소도 콘티용 기준).
- `app.js`: 콘티 곡 링크에 `u=<uid>`, 곡 보기는 `sl`+`u`가 있을 때만 콘티용, 연주 모드는 `items[i].uid`. 콘티 편집 화면은 **고칠 때만** `uid`를 이어 가고 복사·가져오기는 uid를 버림.

### 29-4. 시험
- API: uid 부여·유지·교체, 다른 곡 파일 거부, 빠진 칸 필기 삭제, 복사 시 새 uid, 충돌 병합, 콘티 삭제 정리 — 전부 통과. 브라우저(Playwright): 연주 모드 칸별 겹침(2획/1획), 필기 화면 밑깔림, 저장·서버 동기화, 곡 보기 버튼 문구 — 통과. **실기기(펜슬) 확인 필요.**

## 32. 21차 — 전체 흐름 검토 (v0.21, 2026-11-11)
사용 흐름(첫 접속 → 오늘 → 곡 → 콘티 → 연주 → 더보기·관리자)을 처음부터 다시 점검해 한 차수로 묶었다. 기능 추가는 없고 배치·크기·모양·속도 정리다.

### 32-1. 흐름 정리
- **오늘 화면**: 순서를 "콘티 → 검색 → 이어지는 콘티 → (편집자) 오늘의 보완 제안"으로. 아래 메뉴와 겹치던 버튼(콘티 전체·곡 목록) 삭제. 보완 제안은 화면이 먼저 뜬 뒤 `#fixslot`에 따로 채운다(곡 목록은 콘티 목록과 동시에 요청).
- **잠금 버튼 정리**: `lockBtn(kind,label,go,cls,quiet)` — quiet=true면 잠긴 상태에서 숨김. 곡 목록의 "새 곡", 콘티 목록의 "빠른 콘티", 콘티 보기의 "복사", 오늘 화면의 "빠른 콘티"는 잠겨 있으면 안 보이고, 화면당 대표 버튼 하나(콘티 목록 "+ 새 콘티", 콘티 보기 "편집")만 🔒로 보인다. 권한은 더보기 > 편집·관리에서도 연다.
- **콘티 편집**: 기존 콘티를 고칠 때는 "정보" 칸을 접어 둔다(곡 순서가 바로 보임). 새 콘티는 그대로 펼침.
- **더보기**: 우리 팀(팀·팀 전환) → 내 필기 보관함 → 편집·관리(권한, 악보 현황, 앱 관리) → 기기·앱 정보(접힘: 저장 공간, 화면 진단) → 로그아웃. 행 목록 스타일(`.rows`/`.rowlink`).
- **관리자(앱 관리)**: 세 칸 탭 — 팀·초대 / 추천 태그 / 백업·정리(마지막 칸 기억 `ews_admin_tab`). 팀 카드는 가입코드 복사만 보이고 나머지는 "팀 관리"에 접음. 백업은 독립 카드, 구간 이름 통일은 백업·정리 칸으로. 동작 뒤 다시 그릴 때 스크롤 위치 유지.
- **악보 형식 표시**: 코드 악보 = 코드 기호 "Cm"(코드 색 테두리), 이미지 악보 = 🎼, PDF = 📄. 곡 목록·콘티 보기·필터 칩 공통(`songfilter.js` `badgesHTML`, `app.js` 콘티 보기).

### 32-2. 가볍게
- `ensureMe()`: 열쇠(접속암호·관리자·팀·팀장)가 그대로이고 1분 안이면 `/api/me`를 다시 묻지 않는다(화면 7번 이동에 7회 → 1회). 로그아웃·열쇠 변경·1분 경과·오프라인 표시 때는 다시 묻는다. 직접 새로 확인할 곳은 `loadMe()`.
- 서버 `GET /api/songs`: 검색어가 없으면 `chordpro`·`lyrics_extra`를 읽지 않고 SQL로 `has_chords`만 계산. `GET /api/setlists/:id`도 본문 대신 SQL `has_chords`.
- 곡 목록: 추천 태그 목록(`/api/tags`)을 검색할 때마다 다시 받지 않고 화면당 한 번만.
- 서비스 워커: 화면 파일 대기 4초→2.5초, 데이터 6초→4초. 느려서 저장본을 먼저 보여 준 경우에도 받던 새것을 끝까지 받아 저장(`waitUntil`). 저장본이 없으면 새것을 기다린다.
- 눌림 반응: `touch-action: manipulation`, 탭 하이라이트 제거.

### 32-3. 모양·크기
- **색**: 남녀 모두 무난한 차분한 청록 계열. 라이트 `--brand #2a6670`, 머리글 `--head #1f4e57`, 배경 `#f6f5f2`, 코드색 `#bf4b32`, 강조 배경 `#e8f1f1`. 다크 `--brand #7cc2c8` 등. 색은 `:root` 변수 한 곳에서 바꾼다. 앱 아이콘 4종·`theme-color`·manifest·내보내기 PDF 색도 맞춤.
- **카드·버튼**: 카드 그림자·둥근 모서리 14, 버튼 12. 입력칸 최소 46px, 버튼 44(작은 것 40), 칩 40(숫자는 글자 옆에 나란히), 분류 열기 줄은 버튼 모양, 아래에서 올라오는 창은 모서리 22 + 손잡이 표시.

## 33. 22차 — 전조 송폼(1단계) + 곡 기본 송폼 (v0.22, 2026-11-11)

바탕: `전조-송폼-설계.md`(프로젝트 문서), 인계문서-21차. 사용자 결정(2026-11-11 카드)을 그대로 따른다.

### 사용자 결정
- 전조 단위: **반음 `+n`과 도착 키(`Key:A`) 둘 다 허용**
- 연결 코드: **글자 그대로 괄호에 적기** (자동 계산 안 함)
- 범위: **1단계(표시) + 연주 모드 키 표시**, 그리고 **곡을 등록할 때도 전조를 넣을 수 있게** (언제나 전조되는 곡이 있다)
- 연속 전조: **전조 칩을 그때마다 넣기** (각 칩은 직전 키 기준)

### 글자 규칙 (송폼 한 줄 안)
| 쓰는 법 | 뜻 |
|---|---|
| `Key+2` / `Key-1` | 반음 2개 올림 / 1개 내림 |
| `Key:A` | 도착 키가 A (곡 키에서 계산해 반음 수를 보여 줌) |
| `Key+2(D7 E)` | 전조에 쓰는 연결 코드 (괄호 안은 자유 글자, 30자까지) |
| `전조+2` 처럼 한글 | 읽을 때만 알아본다. 입력 버튼은 항상 `Key…`로 저장 |
- 한 덩어리 칩이다. `Key+2 (D7 E)`처럼 띄어 쓴 괄호도 전조에 붙는다. `Key-1`의 `-`는 송폼 구분 글자가 아니다(`Key-숫자`는 한 덩어리).
- 구간 이름이 아니므로 가사 구간 판별(`Sections.canon`)은 그대로이고, 구분 글자를 나눌 때만 묶는다(`Sections.FORM_TOKEN`·`isKeyChange`). 이관(`migrateForm`)은 전조 칩을 그대로 둔다.

### 화면
- **송폼 입력기(`createFormEditor`)**: 6차 입력기를 `app.js` 맨 위쪽 함수로 빼서 콘티 편집과 곡 편집이 같이 쓴다. 구간 버튼 줄 끝에 **♯ 전조** 버튼 → 패널(반음 −2·−1·+1~+4 / 또는 도착 키 / 연결 코드 / "전조 칩 넣기"). 전조 칩은 코드색 테두리. 선택한 전조 칩에는 ×반복이 없다. 되돌리기·복제·이동·삭제는 구간과 같다.
- **표시**: 콘티 보기·곡 고르는 창·연주 모드의 송폼 줄에서 전조 칩이 `♯ 전조 +2 · G → A (D7 E)`로 코드색으로 보인다(`formHtml`). 키는 그 항목의 키(연주 모드는 지금 소리 나는 키) 기준으로 계산한다. 키를 모르면 반음 수만 나온다.
- **연주 모드 키 표시**: 송폼에 전조가 있으면 위 줄에 `♯ 키 G → A → B`가 한 줄 더 나온다. (악보가 송폼 순서를 따라가지 않으므로 "넘어갈 때 잠깐 뜨는 배지"가 아니라 항상 보이는 키 흐름으로 만들었다.)
- **카톡 텍스트·PDF·표지 이미지**: `전조 +2 G→A (D7 E)`로 풀어 쓴다(`SongForm.formDisplay`). **가사 복사 "송폼 순서대로"**: 전조 자리에 `♯ 전조 +2 (D7 E)` 한 줄이 들어간다.

### 곡 기본 송폼
- 곡 편집 화면 `기본 송폼 · 전조`(접이식, 값이 있으면 펼침): 콘티의 송폼과 같은 입력기. 언제나 전조되는 곡은 여기에 ♯ 전조 칩까지 넣어 둔다.
- **서버**: `songs.base_form TEXT NOT NULL DEFAULT ''`(`ensureColumn`, 최대 200자). 곡 등록·수정·목록·상세에 포함. **`functions` 변경이 있으니 ZIP 전체를 올릴 것.**
- 콘티에 곡을 넣으면 송폼 칸이 그 곡의 기본 송폼으로 미리 채워진다(콘티마다 고칠 수 있음). 송폼 칸이 채워져 있으면 "↺ 지난번 송폼 불러오기" 버튼은 안 보인다(비우면 다시 나옴).
- 곡 편집 임시저장·저장은 숨은 칸 `#bform`으로 다른 칸과 똑같이 동작한다.

### 바뀐 파일
`public/sections.js`(전조 토큰 규칙) · `songform.js`(전조 해석·키 흐름·표시·복사) · `app.js`(입력기 공용화·전조 패널·곡 편집 기본 송폼·표시·연주 키 흐름) · `export.js`(풀어 쓰기) · `style.css`(끝 22차 블록) · `functions/api/[[path]].js`(base_form).

### 시험 (로컬 wrangler + Playwright 375×812, 서비스 워커 끔/켬)
- Node: 전조 글자 해석(`Key+2`·`Key-1`·`Key:A`·한글·괄호 붙이기), 키 흐름(G→A→B), 표시, 이관이 전조를 그대로 둠, 가사 복사 표시.
- 서버 API: `base_form` 저장·조회·목록·300자→200자 절단.
- 화면: 곡 편집에서 전조 칩 넣기·되돌리기·도착 키 입력·저장 → 새 콘티에 곡 추가 시 기본 송폼 미리 채움 → 콘티 보기·연주 모드 표시 → 카톡 텍스트·가사 복사(송폼 순서)·PDF 저장. 페이지 오류 0.
- **21차 미시험 점검 결과**: PDF 내보내기 실물 정상("위와 같음" 표시 포함), 가사 복사 시트 UI 정상, 붙여넣기 반복 추정(V1-C-V2-C-B-C) 정상(같은 가사가 두 번 나오는 1절은 "추정"으로 표시되어 확인 요청), 서비스 워커 설치·오프라인 콘티 열기 정상.
- 실기기(아이폰·아이패드) 확인은 사용자 차례.

### 알려진 한계 / 다음
- 연결 코드는 글자라 키를 바꿔도 자동으로 안 바뀐다.
- 전조 뒤 구간의 코드를 자동으로 올려 펼쳐 보여 주는 "전개 보기"(2단계 3번)는 만들지 않았다.
- 기본 송폼과 "지난번 송폼" 중 지금은 **기본 송폼이 우선**(있으면 미리 채움).

## 35. 25차 — 이미지·PDF 악보 → 코드 악보 변환 (v0.25, 2026-11-11)

- 방식: 앱 안 자동 변환(Cloudflare Workers AI). 보조로 변환 창에 "직접 변환(프롬프트 복사 → Claude 앱 → 결과 붙여넣기)"을 함께 둠.

- 저장: 같은 곡의 코드 악보 본문으로(이미지·PDF 악보는 그대로 유지, 콘티에서 곡마다 코드/이미지 선택은 기존대로).
- 범위: 이미지 + PDF.

### 구현
- 서버 `functions/api/[[path]].js`: `POST /api/transcribe` — 본문은 JPG·PNG·WEBP 한 장(최대 4MB), 편집 권한 필요(`requireEdit`). 변환기는 `TRANSCRIBERS`에서 환경변수 `TRANSCRIBER`(기본 `cloudflare`)로 고르며 `(env, type, buf) → {text, model}` 꼴이라 다른 AI로 교체 가능. Cloudflare 변환기는 `env.AI`(바인딩 이름 `AI`)로 모델 `@cf/meta/llama-3.2-11b-vision-instruct`(환경변수 `AI_MODEL`로 변경)를 부르고, `messages`(시스템+프롬프트)와 `image`(data URI)를 보낸다. 처음 한 번 약관 동의 오류가 나면 `{prompt:'agree'}`를 보낸 뒤 한 번 재시도. DB·R2 변경 없음.
- 앱 `public/imgconv.js`(신규, 순수 함수, Node 시험 가능): `clean`(코드 울타리·잡담 줄 제거, `{title}`류 지시어 제거, `{key: X}`는 키 칸용으로 분리, 구간 이름표를 `Sections.normalize`로 통일, 코드 모양이 아닌 `[...]`는 `[?]`, 코드만 있는 줄은 `[G] [C]` 꼴, 같은 줄이 3번 넘게 이어지면 자름), `merge`(여러 쪽 합치기), `notes`(주의 문구), `MANUAL_PROMPT`.
- 앱 `public/app.js` 곡 편집: "🪄 이미지에서 코드 악보 만들기" 버튼 → 쪽 선택 창(이미지 한 장당 1쪽, PDF는 쪽마다, 한 번에 최대 8쪽, 새 곡의 아직 안 올린 파일도 가능) → 쪽마다 긴 변 1568px JPEG로 만들어 서버에 한 장씩 전송(한 쪽 최대 2분) → 결과를 편집기에 넣고(되돌리기 가능, 본문이 있으면 "뒤에 이어 붙이기" 확인), 키 칸이 비어 있으면 읽은 키를 채우고, 원본 패널을 열고, "AI가 만든 초안" 안내(읽기 어려운 코드 수 등)를 표시. PDF는 pdf.js v3.11.174(Apache-2.0)를 `public/vendor`에 넣어 PDF를 처음 변환할 때만 불러온다(앱 시작 시에는 불러오지 않음).
- `index.html`·`sw.js`에 `imgconv.js` 등록, `style.css` 끝 25차 블록. 설치안내에 6-3단계(Workers AI 바인딩 `AI`) 추가.

### 시험
- Node: `imgconv` 12항목, 서버 변환기 12항목(가짜 `env.AI`: 정상, 약관 동의 후 재시도, 오류 502, 빈 결과 502, 바인딩 없음 500, `AI_MODEL` 교체).
- 로컬 wrangler + 가짜 변환기 + Playwright 375×812: API 7항목(권한 403, PDF·깨진 파일·빈 본문 400, 4MB 초과 413, GET 거부), 화면 18항목(쪽 목록 3개, 선택 해제, 두 쪽 병합, 구간·키·`[?]`·제목 제거, 안내 표시, 원본 패널 열림, 이어 붙이기 확인, 직접 변환 붙여넣기, 파일 없는 새 곡 안내). 페이지 오류 0.
- **미시험: 실제 Cloudflare AI 호출(로컬에서는 Cloudflare 계정 연결 없이 AI를 부를 수 없음)과 실제 악보 사진의 인식 정확도, 실기기.** 모델 입력 형식은 Cloudflare 문서의 llama vision 튜토리얼(`messages` + `image` data URI)을 따랐다.

### 알려진 한계·주의
- 11B급 비전 모델이라 한글 가사 인식과 코드가 얹힌 글자 위치가 틀릴 가능성이 높다. 초안이라는 전제이며, 정확도가 낮으면 모델 교체(`AI_MODEL`)나 다른 변환기 추가(예: Claude API)를 검토한다.
- 변환할 때마다 Workers AI 사용량이 든다(무료 한도 초과 시 청구 가능).
- 서버가 이미지 한 장당 한 번씩 부르므로 여러 쪽은 시간이 걸린다. 한 쪽이 실패하면 거기서 멈추고 앞 쪽 결과만 넣는다.
- 악보에 인쇄된 저작물(가사·코드)을 앱 안에서 옮기는 일이므로 교회 내부 사용 범위를 지킨다(10장).
